Origin of the divergence — what we discarded, and what survived

The framing above is the wrong way round, and correcting it is what made the cause findable. state-actor is not the anomaly: it is the uniform run, costing 15.2–16.7 µs on every class including the address range that exists in no database. jochemnet is the run with anomalously fast classes. So the question is not why state-actor is slow but why jochemnet is fast, and why manual compaction removed some of that speed but not all of it.

One deduction removes most candidate answers before any evidence is needed: under BALANCE geth reads a single account leaf — nonce, balance, storage root, code hash — whose shape does not change whether the account's code is one byte, a 24 KB blob shared by 150,000 accounts, or a byte-unique 24 KB blob. Code lives in a separate table that BALANCE never reads. Structurally identical leaves cannot differ 7× because of what they point at, so the explanation has to be which storage tier answers the read.

The read path that explains it

triedb/pathdb/journal.go:162 forks on exactly one condition. If the journal loads, geth returns the reconstructed layer stack; if it does not, it logs Failed to load journal, discard it and returns a single disk layer with an empty write buffer. And journal.go:197 shows the journal is not metadata: it decodes straight into a live buffer, rehydrating the not-yet-written state.

disklayer.go:171 then reads tiers in order — write buffer, clean state cache, disk. Because the measured statecache is 0.00 B in all three runs, newDiskLayer leaves the clean state cache nil, so the journal-restored buffer is the only warm tier that exists. A run without a journal therefore serves every account read from disk.

Cause

Proven. state-actor's image ships with no pathdb journal, and the benchmark restarts geth for every test, so all 999 lifecycles begin with an empty buffer and no warm tier — hence one flat cost for every class. jochemnet's image ships a 380.15 MiB journal holding 4,248 diff layers, rehydrated on every restart, so part of its state answers from RAM. Manual compaction cannot touch that: the journal is a separate file from the SSTables.

This is a provenance artifact, not a property of either database. The jochemnet image was captured from a running geth that still held unflushed dirty state — corroborated by the ten static 2025 unclean-shutdown markers baked into the same image. state-actor's was synthesised by a tool that writes SSTables directly and never runs a geth that would journal.

Inferred, not proven. That the fast classes are precisely the ones resident in jochemnet's journal. The speed ordering on uncompacted — DIFF_MAX 2.4 < SAME_MAX 2.6 < JUMPDEST 3.1 < MINIMAL 3.2 < EOA 8.3 < NON_EXISTING 17.3 µs — is exactly a hit-depth gradient over a 4,248-layer stack, and geth meters that as dirtyStateHitDepthHist, but the journal's contents were never read.

Still open. Why compaction cost uncompacted four of its five fast classes while leaving DIFF_MAX at ~2 µs, and why it made NON_EXISTING faster (17.3 → 14.3 µs). Both jochemnet runs load an identical journal, so the diff-layer tier cannot be the differentiator; on-disk layout is the remaining candidate and this corpus cannot evaluate it.
